# 交件前審查清單

目的:避免不合格標與廢標(採購法第 50 條:未依招標文件規定投標、投標文件內容不符規定、以不實文件投標等),以及前後不一致。`scripts/audit_bid.py` 能自動檢查標示【自動】的項目,其餘人工逐項複核。

## A. 資格與合規

- [ ] 資格條件逐條有證明文件,且在有效期內(納稅、信用、登記資料等,以須知規定的期限為準)
- [ ] 沒有任何須知列的不得投標情形
- [ ] 協力單位 / 分包有合作同意書,分工範圍與須知的分包限制相符
- [ ] 實績只寫本公司自己的,附證明;協力單位實績另列並標示
- [ ] 沒有編造資格、證照、人員、案例(逐項回查證據)
- [ ] 押標金 / 履約保證金:須知是否收取、金額、方式、繳納期限
- [ ] 電子領標憑據已附(如須知要求)

## B. 格式與份數

- [ ] 文件齊全,對照拆標報告的應繳文件清單
- [ ] 正副本份數、裝訂、頁碼、騎縫章
- [ ] 封套標示與封面標籤:案名、案號、廠商資料、日期
- [ ] 簽章與用印位置符合範本,且經使用者確認
- [ ] 簡報檔(若需要)符合時間與人數限制
- [ ] 投標截止時間(以政府電子採購網公告為準),預留遞送時間

## C. 內容與評審項目

- [ ] 【自動:是否出現】用 `--items` 傳入評審項目,檢查標題或內文是否出現;章節順序是否與評分表一致需人工看目錄
- [ ] 每個子項都有具體做法、量化數字與證據
- [ ] 需求說明書每一條都有回應
- [ ] 時程、里程碑、交付物與履約期間一致
- [ ] 風險與備案已寫
- [ ] 盲評案:【自動】用 `--blind` 檢查公司名、統編、負責人、品牌字樣;Logo 圖檔、圖片內文字、檔案屬性與頁首頁尾需人工檢查

## D. 數字與名稱一致

- [ ] 【自動:單一文件內檢查】專案名稱、案號有出現;跨文件(建議書、標價單、簡報)是否一致需人工對照
- [ ] 【自動:僅公司名稱寫法】公司全稱寫法一致;統編、地址、電話、負責人需人工核對
- [ ] 【自動:單一文件】用 `--price` 傳入最終總價,抓出文件中不符的總價與缺漏;分項金額只提醒。跨文件(標價單、簡報、報價單)仍需人工對照
- [ ] 日期與期間一致(人工):時程、履約期間、簽章日期、簡報日期互相對得起來
- [ ] 預算表小計加總等於總價(重新算一遍)
- [ ] 圖表上的數字與內文一致

## E. 文字品質

- [ ] 【自動】沒有殘留【待補】、TODO、範例文字;出現其他案件字樣會提醒(字樣來自 profile 的 `past_case_keywords` 與 `--stale-terms`,本案相關者用 `--allow-terms` 放行)
- [ ] 【自動】沒有彩色 Emoji(單色幾何字元 ◆ ▸ ▪ ◎ ★ 允許)
- [ ] 【自動】沒有簡體字或中國大陸用語(軟件、信息、視頻、質量、默認等);台灣用語細修用 `shuorenhua-zh-tw`
- [ ] 沒有空話與無法驗證的形容(領先、頂尖、最佳)
- [ ] 專有名詞、人名、機關名稱正確

## F. 過去踩過的坑

- 報價改版後建議書內文仍是舊價:曾發生建議書寫舊總價,報價單已改為較低的新總價。審查用 `audit_bid.py --price <最終總價>` 可抓出文件中不符的總價(已用真實案件實測)。
- 活動類建議書常見疏漏:流程表時間衝突、成果報告書份數前後矛盾、人物資歷誤植、日期仍寫「擇日」、互動活動漏列項目、附錄說明文字被截斷。審查要看表格內的數字與日期,不能只看正文。

## G. 審查報告格式

```
審查報告 {案名} {日期}
blocking(必改)
  1. {問題} -- {位置} -- {建議}
warning(建議改)
  1. ...
通過項
  - ...
需要使用者決定
  - ...
```
