# 規格層與風格層

標書的外觀分成兩層,**規格層永遠優先**。

| 層 | 內容 | 來源 | 可以變嗎 |
|---|---|---|---|
| 規格層 | 紙張、方向、邊界、裝訂邊、中英文字體、各級字級、行距、標號格式、黑白或彩色、頁碼、頁首、頁數上限、封面應載事項、份數、裝訂 | 招標文件(須知、評審須知、需求說明書) | 不可以,每案不同,逐案抽取 |
| 風格層 | 配色、字體搭配(須知沒規定時)、章標題樣式、表格樣式、封面版式、圖表配色 | 風格包(`assets/styles/*.json`) | 可以,每案挑不同的 |

衝突時:規格覆寫風格。例如風格包用微軟正黑體,須知要求標楷體,最後就是標楷體;須知要求黑白,風格包的色彩會自動轉灰階。

## 一、抽取格式規格(階段 1 拆標時做)

到須知、評審須知、需求說明書找這些,逐項記下**原文與出處**,存成 `01_拆標/format.json`(範本:`assets/format.template.json`):

| 要找的 | 對應欄位 | 常見寫法(來自實際標案,已去識別化) |
|---|---|---|
| 紙張與方向 | `paper`、`orientation` | 「以橫書直式編排,紙張大小採 A4 規格紙張」「圖樣得採 A3 規格紙張(請摺頁為 A4 規格)」 |
| 邊界、裝訂 | `margins_cm`、`gutter_cm` | 「左側裝訂」「建請裝訂左側成冊」;邊界多半沒寫,沒寫就用預設 |
| 中文字體 | `font.zh` | 「字體標題為 16 號字標楷體;內文為 14 號字標楷體」 |
| 西文與數字字體 | `font.en` | 多半沒寫;中文指定標楷體時,西文常用 Times New Roman |
| 各級字級 | `font.size_pt`、`h1_pt`、`h2_pt`、`h3_pt`、`table_pt`、`caption_pt` | 同上;表格與圖說若沒另寫,通常視同內文,送件前再確認 |
| 行距 | `line_spacing`(倍數)或 `line_exact_pt`(固定行高) | 「行距為固定行高 22 點」 |
| 標號格式 | `numbering` | 「數字標號依序為壹、一、(一)、1、(1)」 |
| 黑白或彩色 | `color_mode` | 「A4 規格紙張雙面彩印」(彩色)或規定黑白 |
| 頁碼、頁首 | `page_numbers`、`header` | 「附頁碼」「加目錄、編頁碼、加封面」 |
| 頁數上限 | `page_limit`、`page_limit_exclude_pages` | 「不含封面、目錄及附件,建議以不超過 50 頁(單面印製 1 張計 1 頁;雙面印製 1 張計 2 頁)為原則」 |
| 封面應載事項 | `cover_requires` | 「封面上註明廠商名稱」;盲評案則相反,不得出現廠商名稱 |
| 份數、列印 | `copies`、`duplex` | 「一式 10 份」「雙面印刷為原則」 |
| 內容次序 | `order_follows` | 「企劃書內容次序建請按評分表之評審項目次序排列」 |

### 字號與點數(很容易看錯)

須知常寫「16 號字」「14 號字」。這種阿拉伯數字加「號」的寫法,在台灣政府文件裡通常指 Word 的 N 點(pt)。但如果寫的是中文字號(「四號字」「小四」「五號」),要照下表換算。兩種寫法混用或讀不準時,把你的解讀寫進 format.json 的 `_notes`,請使用者確認或向機關釋疑。

| 字號 | 點數 | 字號 | 點數 |
|---|---:|---|---:|
| 初號 | 42 | 四號 | 14 |
| 小初 | 36 | 小四 | 12 |
| 一號 | 26 | 五號 | 10.5 |
| 小一 | 24 | 小五 | 9 |
| 二號 | 22 | 六號 | 7.5 |
| 小二 | 18 | 小六 | 6.5 |
| 三號 | 16 | | |

### 沒有寫的時候

須知沒規定的項目,用預設:A4、直式、邊界 2.2 / 2.0 cm、內文 11 pt、行距 1.5 倍、有頁碼、風格包的字體。**這些預設不是規格,不要當作「符合規定」。**

## 二、挑選風格(階段 2 策略時做,規格抽取完之後)

1. **先看有沒有機關識別**:機關自己有 CI、識別色或指定色票,優先採用,用 `make_style.py --primary ... --accent ...` 轉成風格包。
2. **提 3 個方向,來自 3 個不同流派**(借用 `huashu-design` 的作法:同一流派不推薦兩個,否則看不出差異)。流派與風格對照:

| 流派 | 風格包 | 氣質 |
|---|---|---|
| 資訊建築派 | `navy-institutional`、`editorial-teal`、`tech-slate` | 層次清楚、內容優先、可信 |
| 極簡主義派 | `swiss-grid`、`mono-ink` | 理性、利落、黑白加單一重點色 |
| 東方哲學派 | `paper-quiet` | 留白、克制、像書 |
| 在地與農業 | `green-civic`、`earth-warm` | 溫暖、有土地與人味 |

3. **依案型與機關性格排序**,每個風格包的 `best_for` 與 `avoid_for` 有建議;例如學協會、醫療、資訊系統偏資訊建築派,文化藝術偏東方哲學派或極簡派,農產與地方活動偏在地派。
4. **渲染預覽給使用者挑**:
   ```
   python -I scripts/preview_styles.py --out 03_草稿/style_preview --format 01_拆標/format.json --pdf
   ```
   預覽已套用該案的格式規格,看到的就是照規格後的樣子。`--styles a,b,c` 指定;`--avoid 最近用過的id` 避免與上一案雷同。
5. **每案不同**:預設排除最近用過的風格。若公司 profile 有記錄風格使用歷史,用 `--avoid` 傳入。
6. 使用者選定後,在 spec 設 `"style": "<id>"`,`"format": "01_拆標/format.json"`。

### 擴充風格

- 自訂色碼:`python -I scripts/make_style.py --id x --name 名稱 --primary 1F4E79 --accent E07B39 --banner sidebar --cover band`
- 從 `ui-ux-pro-max` 配色資料轉(若環境有這個 skill):`python -I scripts/make_style.py --from-uiux "Healthcare" --id med-calm --name 醫療平靜`。主色自動加深到可承載白字(對比 4.5 以上)。
- 環境中其他設計類 skill(例如 `huashu-design` 的設計流派、`swiss-creative-mode-template` 的瑞士網格、`brand-designer` 的品牌識別、`oil-ui` 的多風格對比)可作為挑方向與配色的靈感來源。它們是網頁與簡報導向,轉成 Word 時只取**色票、字體氣質、版面密度與層級**,不套用動畫與互動。

### 版面元件與封面圖

除了標題、表格、圖表,還有:`lead` 導言、`stats` 重點數字卡、`callout` 提示框、`steps` 步驟、`twocol` 雙欄對照、`divider` 章節扉頁(見 `spec-format.md`)。這些都讀目前風格與規格,換風格或規格會一起變。

封面圖:風格包的 `art`(`blocks`、`rings`、`bars`、`waves`、`dots`)會用該風格的色票自動生成透明底的幾何圖,**隨機種子取自案名,同風格不同案名構圖不同**。使用者提供主視覺圖時(`case.cover_image`)以使用者的圖為準。

版面用 Word 的真正標題樣式(標題 1 到 3)、圖說樣式與自動編號欄位,所以導覽窗格、PDF 書籤、頁首章名、交叉引用都能用;表格表頭會跨頁重複、列不會被拆到兩頁。

### 風格包欄位

```
colors   primary(章標題與表頭)、secondary(次標題)、tertiary(三級標題)、accent(重點色)、
         tint(淺底)、zebra(表格斑馬紋)、ink(內文)、gray(註解)、line(分隔線)、sub_tint(深底上的淺字)、chart[]
fonts    zh_body、zh_heading、en
banner   filled(主色底反白字)| rule(粗底線)| sidebar(淺底加左側色條)| plain(細底線)
table    zebra(深色表頭加斑馬紋)| lines(淺色表頭)| minimal(無底色)
cover    center(置中)| left(靠左)| band(頂部色帶)
mono     true 時全部轉灰階
art      none | blocks | rings | bars | waves | dots(封面幾何圖)
```

## 三、核對規格(階段 4 審查)

```
python -I scripts/audit_bid.py 成品.docx --format 01_拆標/format.json --pdf 成品.pdf
```

會核對:紙張與方向、四邊邊界與裝訂邊、中文與西文字體、字級(小於規格者)、行距、頁碼欄位、黑白、頁數上限。**不符一律 blocking。** 不能自動核對的:標號層級是否合乎規定(用 `numbering` 產生就會一致)、封面應載事項、圖片內文字、PDF 轉出後字體是否被替換(`--pdf` 只數頁數,不驗字體嵌入)。

## 四、實務提醒

- 指定標楷體時,圖表裡的字也要標楷體(`bid_kit` 會依字體選用系統字型檔 `kaiu.ttf`);沒有該字型的電腦會退回微軟正黑體,送件前在目標電腦開檔確認。
- 轉 PDF 後版面可能因字型替換而位移,頁數上限以最終 PDF 為準。
- 規格寫的是「建請」「建議」「為原則」時,屬於建議,但評審須知可能把格式不符列為扣分或不予評分,保險起見照做。
- 圖樣可用 A3 摺頁為 A4 的案件,需要在 Word 手動插入 A3 橫向節,本 skill 不自動處理。
